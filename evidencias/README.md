## O que cada uma prova

**1. Vídeo.** Que o sistema funciona do começo ao fim. Precisa aparecer: o projeto
subindo, uma issue sendo lida, os agentes trabalhando, os testes passando e o pull
request sendo aberto.

**2. Print da CI.** Que os testes passam na versão entregue. Mostrar a aba Actions
com o check verde.

**3. Planilha de resultados.** Que os números do trabalho são reais. Uma linha por
issue, com: número da issue, se resolveu, tokens gastos, tempo e motivo da falha
quando não resolveu.

**4. Logs.** Que o sistema parou sozinho ao bater no limite. Mostrar o registro da
execução com data e hora.

**5. Capturas.** Que a interface e a saída são legíveis. Pelo menos 5 imagens.

**6. Casos de falha.** Que a gente sabe reconhecer e explicar erro. Mínimo 3 casos,
cada um com: qual era a issue, o que o sistema fez, a causa e o que mudamos.

**7. Histórico de commits.** Que todos participaram. Mostrar o gráfico de
contribuição e a lista de pull requests com o revisor de cada um.

## Checklist final

- [ ] O vídeo tem entre 3 e 5 minutos
- [ ] O print mostra a CI verde
- [ ] A planilha tem as 20 issues
- [ ] Os logs mostram a parada por limite
- [ ] Existem pelo menos 5 capturas de tela
- [ ] Existem pelo menos 3 casos de falha documentados
- [ ] O histórico mostra commits dos três integrantes
- [ ] Os números batem com os do trabalho de pesquisa

## Regras

- Nada de token, senha ou dado pessoal em vídeo, print ou log. Antes de subir,
  revistem cada arquivo.
- Os números precisam ser os mesmos do trabalho de pesquisa. Se a planilha diz 55%,
  o texto também diz 55%.
- Resultado ruim documentado vale mais que resultado bom sem prova. Se o sistema
  acertar 40%, a gente mostra 40% e explica por quê.
- Tudo deve ser da versão final (tag v1.0). Captura de versão antiga não vale.
